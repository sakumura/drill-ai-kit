# Multi-model Vision Check

テスト資料の視覚解析は、最低2系統の独立読解で確定する。Codex単独のOCR・採点判断で完了にしない。

## Model lanes

- Lane A: Codex。ページ画像を直接見て、点数・正誤・問題番号・学習者の回答・正解・根拠を読む。
- Lane B: Claude または Gemini。Lane A の結論を渡さず、同じ画像から独立に読む。
- Lane C: 低信頼や不一致がある時だけ、残る1モデルを追加する。

## Privacy gate

答案・成績画像は学習者の私的データであり、Claude/Gemini/Codex CLI 等の外部モデルCLIに渡すと外部送信になる。このキットは実戦品質のため高性能な外部AI利用を前提にする。性能の低いローカルLLMだけで代替する方針にはしない。

実行前に以下を明示し、保護者の承認を取る:

- 送信先モデル/サービス（例: Claude Code、Codex、Gemini）
- 送る資料の種類（答案、成績表、問題、模範解答、解説）
- 送信先サービスで、学習利用拒否・データ保持短縮・人間レビュー無効化などの設定が可能なら有効化済みか
- 氏名、受験番号、学校名など直接識別子をマスクできているか。理想はマスクだが、現実にマスクできない場合は、そのまま送るリスクを明示する

承認がない場合は外部送信しない。承認なしに別手段で回避実行しない。学習利用拒否の設定や条件を確認できない外部AIには、答案・成績画像を送らない。

## Required fields to compare

- 成績画像: 科目点、平均点、偏差値、順位、受験者数、評価欄。
- 答案: 大問/小問番号、配点、学習者の回答、丸バツ、部分点、空欄。
- 問題: 問題本文、図表条件、選択肢、単元。
- 模範解答/解説: 正解、別解、採点基準、解法の要点。

## Prompt rule

各モデルには「このページだけから読み取れる事実」と「推測」を分けて出させる。既にCodexが読んだ結論を先に見せない。出力は可能ならJSONにする。

Minimum prompt shape:

```text
画像/PDFページを読み、見える事実だけをJSONで返してください。
科目、資料種別、ページ、問題番号、配点、正解、答案上の回答、正誤、部分点、読み取り不能箇所を分けてください。
推測が必要な値は null にし、notes に理由を書いてください。
```

## Resolution loop

1. 2モデルの結果を field 単位で突き合わせる。
2. 一致した field だけ `confirmed` にする。
3. 不一致は該当箇所をcropまたは高dpi再レンダリングして再解析する。
4. それでも割れたら3つ目のモデルを使う。
5. 3モデルでも割れる場合は、元資料の該当箇所を再読し、根拠画像名・ページ・座標をメモして結論を決める。
6. ソース欠落・破損以外の理由で `unresolved_questions` を残さない。

## Stop conditions

完了してよい条件:

- 2モデル以上を使った。
- 全資料のページ対応表がある。
- 点数・誤答・正解・tier・弱点反映がすべて根拠付きで確定した。
- `analysis.json` の `unresolved_questions` が空。

完了してはいけない条件:

- 画像解析が1モデルだけ。
- PDFの一部ページを見ていない。
- 成績画像の数値、答案の正誤、問題番号対応、模範解答のいずれかに未確認が残る。
- 「たぶん」「読みにくいが」で成果物更新へ進む。
