# 問題生成ルール（禁則集）

レッスン問題（questions テーブル）を生成するときに**必ず守る**ルール。briefing Phase 4b / generate-drill-lesson / 手動パッチSQL のすべてで共通。

## 1. 英略語禁止

**ダメ**: `LCM` `GCD` `Σ` `∞` などの英略語を問題文・solution_steps・common_mistakes 内で使う

**やる**: 小学生が初見で読めない英略は日本語で書く
- `LCM(2,4)` → `最小公倍数=4`
- `GCD(12,18)` → `最大公約数=6`
- `LCM(x,y)=z` → `xとyの最小公倍数はz`

**理由**: 対象は小学生。英略は認知負荷を上げるだけで、問題の本質とは無関係。

**例外**: 本人が学校でその略語を学んだ後なら使ってよいが、現状は未習。

**再発防止用チェック**:
```bash
grep -n "LCM\|GCD" data/lessons-handwritten/*.json
# ヒット0件であること
```

## 2. 数式記号の表記ルール

**ダメ**:
- `×÷` を全角、`+-` を半角で混在（例: `8×5+3` → 視覚的にガタつく）
- 全角 `＋` `−` に統一（グリフ固有の大小差が残る。`＋` が大きく、`−` が小さく見える）

**やる**: **半角寄り記号 + 全演算子の前後に半角スペース必須** を採用

| 記号 | Unicode | 書き方 | 例 |
|-----|---------|-------|------|
| 足す | `+` (U+002B ASCII) | ` + ` 前後スペース必須 | `8 + 5` |
| 引く | `-` (U+002D ASCII) | ` - ` 前後スペース必須 | `40 - 4` |
| 掛ける | `×` (U+00D7 Latin-1) | ` × ` 前後スペース必須 | `8 × 5`、`2 × 20` |
| 割る | `÷` (U+00F7 Latin-1) | ` ÷ ` 前後スペース必須 | `8 ÷ 2` |
| 等号 | `=` (U+003D ASCII) | ` = ` 前後スペース必須 | `8 × 5 = 40` |
| 数字 | 半角 `0-9` | — | |
| カッコ | 全角 `（）` | 直内側はスペース無し | `（8 + 5）` |

**代表例（正しい書き方）**:
- `8 × 5 ÷ 2`
- `2 × 20 + 2 × 30 - 2 × 2`
- `（□ + 8） × 5 = 60`
- `分母4 + 4 = 8、分子1 + 1 = 2`
- `三角形の面積 = 底辺 × 高さ ÷ 2`
- `交差部分（2 × 2 = 4）を2回数える`

**例外**: URL文字列、SVG属性値 (`viewBox="-20 0 260 170"` 等)、プログラムコード上の `()` は対象外（データ側の表示文字列のみ全角化）。

**理由**:
- ASCII 半角 `+` `-` と Latin-1 `×` `÷` は日本語フォントでグリフサイズに差がある（半角は詰まって見え、×÷は全角幅で大きく見える）
- **全演算子の前後に半角スペースを入れると、余白がサイズ差を吸収して式が揃って見える**
- 等号 `=` も同じルール。前後スペースで左辺・右辺の関係が視覚的に明確
- ASCII の `*` `/` は算数表記として違和感があるため不採用（`/` は分数表記と衝突するためなおさら禁止）

## 3. 解法理解型と値ドリル型の使い分け

- 弱点単元（スコア ≥ 50）の**導入1-2問**: 解法理解型（立式選択・手順選択・公式穴埋め・誤答診断）
- 弱点単元の**反復**: 値ドリル型（SVG付きで視覚化）
- 新規導入単元の**最初の1-2問**: 解法理解型
- それ以降: SVG付き値ドリル
- 図形問題は**必ず SVG 付き**（文章のみで寸法列挙は禁止）

## 4. 選択肢（hints 配列）のルール

- `single_tier` は3要素: `[正解, 誤答1, 誤答2]`
- `two_tier` / `evidence_first` は6要素: `[Step1プロセス正解, Step1誤答1, Step1誤答2, Step2最終答え, Step2誤答1, Step2誤答2]`
- `single_tier` は `hints[0]` と `answer`、`two_tier` / `evidence_first` は `hints[3]` と `answer` が**厳密一致**（フロント判定の都合）
- 誤答は**典型的な間違いパターン**を入れる
  - ÷2 忘れ（三角形→平行四辺形と混同）
  - 公式誤用（×÷の入れ替え）
  - 単位変換ミス（cm² ↔ cm）

## 4-禁則. 正解肢は「答えそのもの」限定

**最終答えの正解肢（`single_tier` は `hints[0]`、`two_tier` / `evidence_first` は `hints[3]`）/ `answer` は値・数値・単語・短答文のみ。以下を絶対に書かない:**

- 解法ヒント文（例: 「等積変形: 三角形の頂点を底辺と平行線上で動かしても面積不変」）
- 公式文字列（例: 「平行四辺形の面積 = 底辺 × 高さ」「u段→e段＋る」）
- 解法概念の説明文（例: 「気持ち・考えが自然に湧く場面は自発表現」）
- 解法手順の要約（例: 「長方形を分割して個別計算」）

**正解肢の形式基準:**

| 問題タイプ | 正解肢の形式 | 例 |
|-----------|-------------|----|
| 計算・数値求解 | 数値（単位付き可） | `96`, `127.5cm²`, `8` |
| 分数 | 既約分数1つ | `2/3`, `13/12` |
| 変換・活用 | 変換後の単語1つ | `話せる`, `会える` |
| 意味判定 | 分類ラベル1語 | `可能`, `受身`, `自発` |
| 漢字 | 正しい漢字表記 | `手紙`, `学校` |
| 本文合致選択 | 本文の答えそのもの（1-2文） | `新参の子はサッカリなんか夢中になっていなかったから` |

**解法ヒント文・公式文字列・解法概念は `hints[1] / hints[2]`（誤答/distractor）に入れるのは可**。誤答として選ばせることで「解き方を理解しているか」を試せる。**ただし正解扱いにしてはならない**。

**再発防止の二重防護:**

1. **生成時**: このルールは LLM への問題生成プロンプトに必ず流し込む（`generate-drill-lesson/SKILL.md` Step 4-5）。
2. **生成後**: `scripts/validate_lesson_format.py` が機械検出し、1問でも NG ならレッスン全体を不合格にして再生成する（`generate-drill-lesson/reference/gates.md`）。

## 4b. 想定解答時間（難易度ターゲット）

**1問の想定解答時間は 15〜20 秒**。30問10分 = 平均20秒ペースが基準。

**観測された問題**: 「解法理解型の立式選択」は3択UIのガイドレール効果によって再認テスト化しやすく、平均解答時間が想定（15〜20秒）を大きく下回る・正答率がほぼ100%に張り付く、といった兆候が出たら実力測定になっていないサインである。その場合は次の設計方針へ移行する：

### 新難易度ポリシー

1. **立式選択を30%以下に抑制** — 「式はどれ？」形式は1レッスン9問まで
2. **計算結果選択を主軸に** — 「= ?」形式で数値選択（学習者が実際に筆算・暗算する必要がある）
3. **2ステップ以上の問題を50%以上** — 「通分 → 計算」「底辺・高さを読み取る → 面積計算」のように、**最終ステップだけで解ける問題を作らない**
4. **近似誤答を選択肢に** — 典型ミスだけでなく「1違い・桁違い・単位違い」を混ぜて見分けを難化
5. **図形は条件の一部を文章化** — SVG+寸法ラベルだけで完結させず、文章でも条件を提示（例: 「縦は横の半分」）
6. **想定時間を超えそうな問題はスモークで検知** — `time_spent_sec` の中央値が8秒未満なら難化余地あり

### 国語の難化ポリシー

1. **本文は定例テスト相当の情報量** — 既存の「短文→即答」型を減らし、複文・接続詞の絡む3〜5文を本文に
2. **否定選択 (hitei-sentaku) と因果関係 (inga-kankei) を毎レッスン3問以上** — 誤答傾向として現れやすい弱点カテゴリ
3. **誤答選択肢に「本文に書いてある内容（ただし問われていない要素）」を混ぜる** — 「本文一致だから正しい」と飛びつく子の弱点を突く

## 4c. 難易度ジャンプアップポリシー

**背景**: §4b 適用後も平均解答時間が目標（20秒/問）に遠く届かない場合、実力の上限付近を引き出せていない可能性が高い。

**設計上の前提**: タイマーの秒数はブラウザ・OS操作（バックグラウンド化、タブ切り替え等）で容易に回避されうる計測値であり、難易度調整の根拠として単独で信頼できない。タイマーは固定値（算60秒・国30秒、`useGameTimer.ts`）とし、**難度調整は問題内容そのもので行う**。

### 狙い

**主教材・定例テスト・公開模試の応用問題レベル**に近づけ、「ちょっと考えないと解けない」状態を作る。結果として30問10分（1問20秒）に自然収束する。

### 算数のジャンプアップ

1. **3ステップの問題を主軸に** — 「条件整理 → 立式 → 計算」「図形寸法の読み取り → 公式選択 → 計算」のような3段階思考を要求
2. **複合図形を標準扱い** — 単一の三角形・長方形ではなく、「長方形 + 半円」「台形 - 三角形」「L字 + 円」のような複合形を既定
3. **面積・長さ・角度の逆算** — 「面積から底辺」「円周から直径」ではなく「面積+比から両辺」「弧長+中心角から半径」のような2段逆算
4. **文章題に条件を2-3個絡める** — 和差算 × 倍分、速さ × 割合、比 × 逆算のような複合パターン
5. **図形条件の一部を文章化** — SVG+ラベルに加えて「下底は上底の2倍」「高さは底辺より5cm短い」など文章でも条件付与
6. **小5範囲厳守** — 文字式（x°, x+15°）・一次方程式・中学数学の概念は禁止。**数量関係や線分図で表現する**
7. **d4 比率を 50% 以上** — d3は基礎問題のみ、応用は d4、新単元導入は d3→d4 の順

### 国語のジャンプアップ

1. **本文を5-10文の複文で構成** — §4b の3-5文から一段上げる。接続詞（しかし/それなのに/だからこそ/とはいえ）、指示語（それ/その/そういう）、比喩、情景描写を必ず絡める
2. **複数描写を統合する心情判断** — 「A の場面 + B の場面 → 統合心情」のように、1文の手がかりだけでは解けない問題を主軸に
3. **選択肢を2-3文の内容照合** — 選択肢自体が1文ではなく複文で、本文の複数箇所と突き合わせる必要がある形式
4. **語彙を塾教材レベルに引き上げ** — 既存の「情景」「異常」「豊富」より踏み込む。慣用句（「水を打ったよう」「気が置けない」）、四字熟語、抽象名詞（「矛盾」「葛藤」「妥協」）を問題文・選択肢に混ぜる
5. **説明文は逆接・譲歩・仮定の接続詞を必須絡め** — 「しかし」「〜とはいえ」「もし〜なら」を含む論理構造を読み解かせる
6. **敬語は尊敬謙譲混在の文で判定** — 単独の動詞ではなく、1つの文に2-3の敬語が含まれる形で正誤を問う
7. **d4 比率を 50% 以上** — 漢字・語彙基礎以外は d3→d4 中心に

### 禁則（再確認）

- 3択UIのガイドレール効果を避けるため、**立式選択は算数で 20% 以下**（従来 30% → 引き下げ）
- **答えが選択肢に並ぶだけで判別可能な問題を作らない** — 例: 「答えは整数」で整数選択肢1つしかなければ無効
- 算数の数値計算は 15〜30 秒で**筆算を要求**するレベル（+/- で暗算できる3-4桁の足し引きは基本禁止、乗除の2段計算を主軸）

### 答え漏洩禁止

dogfood（実機QA）で、SVG ラベルに答えの度数・長さを直接記載していた／漢字問題文の括弧内に答え熟語を記載していた、という答え漏洩が複数問で見つかったことがある。再発防止の絶対ルール：

1. **図形問題の SVG ラベル**: 答えとなる数値（角度・辺の長さ・面積）は `?°` `? cm` `? cm²` のように `?` で隠す。**問題条件の既知数値（前提の辺・角度）のみ表記する**
   - NG: 「頂点 A の内角は何度？」の SVG で `<text>67°</text>` と表示 → 答え漏洩
   - OK: `<text>?°</text>` または A の位置にラベルなし
2. **漢字問題の問題文**: 問題文の括弧内・注釈内で **答えとなる漢字（答え熟語を含む）を絶対に書かない**。答え漢字はすべて**ひらがな**で書く
   - NG: `「かんげき（感激）的だった」の「かん」の漢字は？` → 括弧内で答えが丸わかり
   - OK: `「かんげき的だった（強く心を動かされた）」の「かん」の漢字は？` → ひらがな＋意味説明
   - OK: `「せいかく（人の行動や考え方のくせ）」の「せい」は？` → ひらがな読み＋意味
3. **選択肢（hints）に関する漢字・類義語・選択肢提示**: これは問題上必要なので、`（同音異字: 感／管／監）` のように**選択肢として提示する記述は可**。**問題文中の文脈内で答えを書いてはならない**
4. **チェックスクリプト**: 生成後に `grep -oE '答え漢字' 該当SQL` or `python` で問題文／SVG 内に answer が含まれないかを確認すること

**再発源**: logic-coder が「親切心で」答えを図や注釈に含めてしまう傾向がある。生成プロンプトで明示的に「SVGに答えの数値は書くな／問題文の括弧内に答え漢字を書くな」と指示し、生成後は 1次チェッカー（`answer in question_text or answer in figure_svg`）を走らせること。

## 4d. 難易度の再定義 ─ 志望校アンカー基準

### 設計思想

d1-d5 の抽象 5 段階は主観判定になりがち（logic-coder が「d4なら難しい」のような曖昧判断をする）。**志望校の算数過去問を偏差値 50（合格最低ライン）の基準問題とし、各 d レベルに具体的な同型問題をアンカー**する。これにより難易度が**同型判定ベース**になり、主観判定を排除する。

**一次ソース**: `data/target-school/difficulty-anchor.md`（d1-d5 の代表問題と配点・想定正答率の紐付け）
**分析根拠**: `data/target-school/math-analysis.md`（2026 1 期/2 期/3 期 算数の大問単位分析、合格者平均 67.5/100 からの逆算）

### 定義（志望校アンカーベース）

| 難易度 | 志望校アンカー（代表） | 意味 | 偏差値 50 想定正答率 |
|-------|---------------------|------|-------------------|
| d1 | 2026 1 期 大問 1(1) の前半（2-3 桁四則 1 段） | ウォームアップ・既習復習 | 95-100% |
| d2 | 2026 1 期 大問 1(1)(4)(5)、大問 3(1) | 公式直接適用 1-2 ステップ | 80-90% |
| d3 | 2026 1 期 大問 1(6)(7)、大問 2(1)(2) | 標準文章題・単元単独 2-3 ステップ | 60-75% |
| d4 | 2026 1 期 大問 1(3)、大問 2(3)-(6)、大問 3(2) | 複合 2-3 ステップ・逆算含む | 30-50% |
| **d5** | **2026 1 期 大問 3(3)、2 期 大問 2(5)、3 期 大問 3(4)** | **発展 3 ステップ以上・独特発想** | **10-20%** |

### 合格ライン逆算（算数合格者平均 67.5/100）

| 戦略 | 大問 1 | 大問 2 | 大問 3 | 合計 |
|------|-------|-------|-------|------|
| **本命ルート** | 9/9 = 45 | 4/6 = 24 | (1) = 5 | **74** |
| **最低ライン** | 8/9 = 40 | 3/6 = 18 | (1)(2) = 12 | **70** |

**結論**:
- **大問 1 全問正解が絶対条件**（d2-d3 主体、落とすと致命傷）
- **大問 2 は 4 問以上取る**（d3-d4 主戦場）
- **大問 3(1) は必ず取る**（d2-d3、独立で取れる構造）
- **大問 2 最難問・大問 3(3)(4) は捨てても合格可能**（d5 領域）

### 同型判定フロー（generate-drill-lesson Step 4-5 連動）

各問題について:

1. 作る問題の**単元 × ステップ数 × 逆算有無**を特定
2. `data/target-school/difficulty-anchor.md` と照合:
   - **完全同型**（単元・ステップ数一致）→ アンカーの d を採用
   - **部分同型**（単元一致、ステップ差あり）→ 隣接 d を参照（軽ければ -1、重ければ +1）
   - **同型なし** → 定例テスト範囲を優先し、`meta.target_anchor: none` を記録
3. 問題 JSON の `meta.target_anchor` に以下を記録:
   ```json
   {
     "target_anchor": "2026-1 大問3(2)",
     "match_type": "exact | adjacent | none",
     "difficulty_from_anchor": "d3",
     "steps": 2,
     "operations": ["分数÷整数", "比の逆算"]
   }
   ```
4. 同型判定を問題の memo として残す（レビュー時の監査証跡）

## 4f. 問い方品質 5 原則（エージェントの教育知識を 100% 引き出す）

### 背景

「パターン暗記特化（d3-d5 `single_tier` + 暗記テーブル）」の構造ルール（必須フィールド・選択肢の値域・暗記テーブル抽出）だけを厳密に守ると、「中心角 45 度のおうぎ形は円全体の何分のいくつ？（ヒント: 45 ÷ 360 を約分）」のような、**核となる暗記事実から逆算させるだけの問題**に偏りがちになる。さらに d4-d5 が最終数値直接型 `single_tier` に偏ると、プロセス理解を問えない。本来は「ピザを 8 等分すると 1 切れの中心角は何度？」のように、**核を順方向で問う**か、d4-d5 では方針・基準量・式・根拠を先に問うべきである。

エージェントは小学生向けの王道出題パターンを内側に持っているはずなのに、構造ルールだけを守って「無難で薄い問い方」に流れている。これを構造的に解消するため、問い方そのものの品質を測る 5 原則を以下に定義する。

### 出し惜しみ禁止宣言（鉄則）

エージェントは小学生向けの教育ロジックを毎レッスンで 100% 出し切る。

- 「無難で薄い問い方」を採用してはならない
- 「核となる暗記事実を逆算で答えさせるだけの問題」を主役にしてはならない
- 世界共通で効くことが知られている王道パターン（生活実感アンカー、順方向出題、定型表現連結）が `generate-drill-lesson/reference/lesson-design-rules.md` にある限り、それを優先採用する
- 新しい単元で王道が未収録なら、執筆過程でエージェントがその場で捻り出してカタログに追記してから書く

### 5 原則

| # | 原則 | 一文ルール |
|---|------|----------|
| Q1 | **順方向優先** | 暗記テーブルの「核 → 即答」を順方向で問うのが主、逆方向（結果から核を逆算）は副。1 レッスン内で順方向 ≥ 60%、逆方向 ≤ 40% を目安 |
| Q2 | **生活実感アンカー必須** | 各暗記行に「ピザ / ケーキ / 時計 / お金 / 地図 / 家族 / 教室 / 通学路」等の生活素材を 1 つ紐づけ、`question_text` に登場させる |
| Q3 | **即答性 15-60 秒** | d3=15 秒 / d4=30 秒 / d5=60 秒 で答えに到達可能。中間計算が 2 段以上必要なら設計し直し（既存 §4b の想定解答時間と整合） |
| Q4 | **典型誤答の質** | distractor は「**隣の暗記行**」（8 等分↔6 等分、効果↔効能）から取る。§4-禁則の禁止 distractor とも整合 |
| Q5 | **定型表現連結** | 中学受験で世界共通に効く語呂・連結（「正八角形→中心角 45°」「N 等分→360/N 度」「原因→だから→結果」）を毎単元 1 個は使う |

### 原則ごとの詳細

#### Q1: 順方向優先

**順方向の定義**: 暗記テーブルの「典型パターン入力 → 即答すべき値」をそのまま問う形式。

例（中心角テーブル: 30°↔1/12, 45°↔1/8, 60°↔1/6, 90°↔1/4, 120°↔1/3, 180°↔1/2）:

| 方向 | 問い方 | 答え | 評価 |
|------|-------|------|------|
| **順方向** | 「正八角形の中心角は何度？」 | 45° | 核を直接覚える |
| **順方向** | 「ピザを 8 等分。1 切れの中心角は？」 | 45° | 核 + 生活実感 |
| 逆方向 | 「中心角 45° のおうぎ形は円全体の何分？」 | 1/8 | 結果から核を逆算 |
| **NG（逆算過多）** | 「45 ÷ 360 を約分すると？」 | 1/8 | 中間計算が主役、核は出ない |

逆方向の問題が出てもよいが、**同テーブルから順方向の問題が他 position に必ずあること**を構成表で確認する。

#### Q2: 生活実感アンカー必須

各暗記テーブルの行に、以下のような生活素材を 1 つ紐づける:

| 単元 | 生活実感アンカー候補 |
|------|------------------|
| 円・おうぎ形 | ピザ / ホールケーキ / ホットケーキ / 時計の文字盤 / バウムクーヘン |
| 角度・図形 | 道路標識 / マンホール / 折り紙 / ナット |
| 割合・百分率 | お小遣い / 割引 / クラスの人数 / 投票 |
| 速さ | 通学路 / 自転車 / 電車 / 散歩 |
| 食塩水濃度 | 麦茶 / ジュース / スープ |
| 場合の数 | じゃんけん / トランプ / 班分け |
| 接続語 | 天気と試合 / 練習と結果 / 家族の予定 |
| 性格描写 | 教室 / 部活 / 公園 / 家族の出来事 |
| 慣用句 | 身体（目・耳・手・足）/ 動物（犬・猫・馬）/ 自然（風・雨）|

`question_text` のどこかにこの素材が登場すれば OK。「半径 12cm のおうぎ形…」のように数値のみで構成する問題は、生活実感アンカーなしと見なされ、書き直し対象。

#### Q3: 即答性 15-60 秒

- **d3 = 15 秒**: 暗記テーブル lookup 1 ステップで答えが出る（「ピザ 8 等分→45°」）
- **d4 = 30 秒**: テーブル lookup + 1 段計算（「半径 6cm 中心角 60°→面積は？」のように lookup した 1/6 を円全体にかける）
- **d5 = 60 秒**: lookup + 2 段計算（ヒポクラテスの月など、公式 lookup + 直角三角形面積計算）

中間計算が 3 段以上になる問題は d5 でも書き直し対象。

#### Q4: 典型誤答の質

distractor は以下の優先順位で取る:

1. **隣の暗記行**: 同じテーブルの最も近い行（45° の問題なら 60° の行の値、または 30° の行の値）
2. **公式・概念の混同**: 半径 ↔ 直径、面積 ↔ 周長、直喩 ↔ 隠喩、効果 ↔ 効能
3. **直近誤答ログの実誤答**: プレイログで実際に選ばれた誤答

§4-禁則 + §4b 「禁止 distractor」と整合: ÷2 / ×2 / 桁ずらし / 「場合による」「わからない」は使用禁止。

#### Q5: 定型表現連結

各単元には中学受験で世界共通に知られている「連結」がある。これを 1 レッスン中に 1 個は出題する。

| 単元 | 定型連結 |
|------|---------|
| 円・おうぎ形 | 「正 N 角形 ⇔ 円を N 等分 ⇔ 中心角 360/N °」「N 等分のおうぎ形は円の 1/N」 |
| 多角形 | 「内角の和 = 180 ×（N − 2）」「外角の和はいつも 360°」 |
| 割合 | 「比べる量 = 基準量 × 割合」「もとにする量 = 比べる量 ÷ 割合」 |
| 速さ | 「は・じ・き」（速さ・時間・距離）/「分速 × 60 = 時速」 |
| 接続語 | 「原因 → だから → 結果」「期待 ↔ しかし ↔ 結果」 |
| 慣用句 | 「目から鱗 = 急に分かる」「耳が痛い = 自分のことで都合悪い」 |

これらの連結を、ヒント文・solution_steps・common_mistakes のどこかで言語化する。

### 運用ルール

1. Step 4.2.2-pre2 で暗記テーブルを作るとき、各行に **生活実感アンカー** を必ず 1 つ書き添える
2. Step 4.2.3 で各問を執筆するとき、**Q1-Q5 を順に発話して**確認してから書く
3. Step 4.2.8 (B) エージェント自己解答ゲートで、各問について 5 項目（核 / 順逆 / アンカー / 即答性 / distractor 出典）を発話で宣言する
4. 単元別の具体テンプレは `generate-drill-lesson/reference/lesson-design-rules.md` を参照

### 単元別カタログとの関係

5 原則は**総論**（科目を問わない普遍ルール）。科目別の各論は `generate-drill-lesson/reference/lesson-design-rules.md` を参照する。カタログにない単元を扱うときは、エージェントが執筆過程で具体テンプレを先に定義してから本文を書く。

## 5. SVG の共通クラス

CSS で `.question-flash__figure svg` 配下に定義済み。直書きの stroke/fill は禁止。
- `.fig-shape` 基本輪郭
- `.fig-shaded` 影領域（半透明グレー）
- `.fig-dashed` 補助線（点線）
- `.fig-label` 寸法・頂点テキスト
- `.fig-angle` **直角マーク専用（Lコマンドのみ）**

viewBox は原則 `0 0 240 170`、ラベル見切れ時のみ `-20 0 260 170` 等に拡張。

### 角度表現の禁則

**ダメ**: `.fig-angle` の `d` 属性に **Arcコマンド（`A`）を使って角度弧（半円）を描く**

```xml
<!-- NG: 角度弧の sweep-flag と start/end 座標を幾何計算する必要があり、LLM生成ではほぼ崩れる -->
<path class="fig-angle" d="M 44 145 A 16 16 0 0 1 58 137"/>
```

**やる**: 角度は**数字ラベル（`<text class="fig-label">60°</text>`）のみで示す**。頂点の位置に数値を置けば「どこの角度か」は十分伝わる。

```xml
<!-- OK: 数字ラベルだけ -->
<text class="fig-label" x="28" y="166" text-anchor="middle">60°</text>
```

**例外**: **直角マークは L コマンドのみで書く**。これは座標直交なので崩れない。
```xml
<!-- OK: 直角マーク (L-only, Aコマンドなし) -->
<path class="fig-angle" d="M 90 120 L 100 120 L 100 130"/>
```

**理由**: 角度弧は頂点の位置・2辺の方向・sweep-flag の整合が必要で、LLM が生成すると sweep-flag の向きや start/end の座標が 2辺の内側からずれる崩れが発生しやすい。実際に LLM 生成の角度弧SVGが軒並み崩れた事例があり、全削除で対応した。

## 6. 既存の類似ミス履歴（再発防止・設計判断の記録）

各ルールがなぜ存在するかの背景。実際の学習ログの数値・日付・個別レッスンIDは含めない。

- 通分問題で英略語（`LCM`等）を併記していた事例 → §1（英略語禁止）を新設
- 演算子の全角・半角混在で式の見た目がガタつく事例 → §2（数式記号の表記ルール）を新設
- 全角の `＋` `−` はグリフの大小差が残り読みにくい事例 → 半角寄り記号＋前後スペース必須のルールへ変更
- 半角カッコが全角かな・漢字と並ぶと視覚的に浮く事例 → カッコは全角 `（）` に統一
- LLM 生成の角度弧SVGで sweep-flag・座標が崩れる事例が頻発 → 角度は数字ラベルのみに簡素化（§5）
- 3択UIの再認効果で難易度が形骸化しやすい事例 → 新難易度ポリシー（§4b）を確立
- 正解肢に解法ヒント・公式・概念の文言が混入し、本来不正解の選択でも正解扱いされていた事例（2回発生） → §4-禁則を新設、`validate_lesson_format.py` による機械検出を実装
- レッスン生成の入口を `generate-drill-lesson` に統合。d4-d5 の最終数値直接型 `single_tier` を R22 reject に格上げし、配分の正本を `generate-drill-lesson/reference/ownership-contract.md` に移管
- 通塾日のレッスン負荷が高すぎた事例 → 通塾日（火・金）レッスンサイズを縮小する運用ルール化。詳細な配分は `generate-drill-lesson/reference/ownership-contract.md` を正本とする
